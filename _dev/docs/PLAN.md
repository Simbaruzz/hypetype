# hypetype v2 — ТЗ на переписывание (AutoHotkey v2)

Техническое задание для полного переписывания hypetype с AutoHotkey v1.1 на AutoHotkey v2 с устранением архитектурных проблем. Документ самодостаточен: вся необходимая информация — здесь и в `FORMAT.md` (спецификация формата конфига, лежит рядом; читать **обязательно перед началом**).

---

## 0. Контекст проекта

hypetype — трей-утилита для Windows, позволяющая вводить любые Unicode-символы с клавиатуры через правый Alt (идейный аналог раскладки Бирмана). Ключевой трюк: через реестровый `Scancode Map` правый Alt переназначается на «виртуальную» клавишу (`vkA9`), благодаря чему хоткеи hypetype не конфликтуют с Alt-сочетаниями Windows, Adobe, Figma и т.д. Это **главная фича продукта** — не сломать.

Вторая киллер-фича: на одну клавишу можно назначить **последовательность символов** (каомодзи, дивайдеры вроде `␣·␣`, эмодзи-комбо). В v2 она становится первоклассной (см. FORMAT.md §4.2).

Текущий код: `scr/main.ahk` (340 строк) + `scr/editor.ahk` (455 строк), AHK v1.1. У программы есть живые пользователи с настроенными `config.ini` старого формата — обратная совместимость через миграцию обязательна.

### 0.1 Цели

Та же программа, тот же UX, но: AHK v2, модульная архитектура, кросс-платформенный формат конфига (FORMAT.md), безопасная работа с реестром, без мёртвого и хрупкого кода.

### 0.2 НЕ-цели (не делать в этом подходе)

- Никаких новых пользовательских фич сверх описанных.
- Не менять визуальный дизайн редактора сверх необходимого для портирования на v2 Gui.
- Не делать мультиязычный интерфейс (все строки — русские, как сейчас, но собрать их в один блок констант для будущей локализации).
- Не делать автообновление, подпись сертификатом, инсталлятор.
- Не трогать macOS-версию (она будет рефакториться отдельно по FORMAT.md).

## 1. Архитектура

Пять файлов в `src/` (переименовать из `scr/` — попутный фикс):

| Файл | Ответственность | Что НЕ делает |
|---|---|---|
| `hypetype.ahk` | Точка входа: init, трей-меню, версия, связывание модулей | не трогает файлы и реестр напрямую |
| `config.ahk` | Класс `Config`: путь, загрузка, сохранение, миграция, дефолты. **Единственный** код, читающий/пишущий config.ini | не знает про GUI и хоткеи |
| `registry.ahk` | Классы `ScancodeMap` (виртуализация) и `Autostart`. **Единственный** код, трогающий реестр | не показывает MsgBox (возвращает статусы/ошибки наверх) |
| `input.ahk` | Регистрация хоткеев, обработчик ввода, диакритический режим, нормализация NFC | не парсит конфиг сам — берёт данные у `Config` |
| `editor.ahk` | GUI редактора раскладки, окно правки клавиши, валидация ввода | не пишет файл сам — зовёт `Config.SetKey()` |

Правила:
- `#Requires AutoHotkey v2.0` в каждом файле.
- Ноль глобальных переменных-«вёдер»; состояние — в классах/замыканиях. (В v1 было 48 глобалов `Btn_SCxxx` — в v2 GUI-контролы это объекты, такие глобалы запрещены.)
- Версия приложения — **одна** константа `APP_VERSION` в `hypetype.ahk`, используется в трей-тултипе и везде. (В v1 версия была захардкожена строкой и устарела относительно релиза.)
- Все пользовательские строки (сообщения, меню) — в одном блоке констант в `hypetype.ahk`.

## 2. Модуль Config (`config.ahk`)

Реализует FORMAT.md полностью. Публичный API:

```
Config.Load()                      ; определить путь, загрузить/мигрировать/создать дефолт
Config.Save()                      ; атомарная запись по FORMAT.md (round-trip!)
Config.GetKey(w3cName) -> {alt, altShift}   ; строки готовых символов (уже декодированные из hex)
Config.SetKey(w3cName, alt, altShift)       ; обновить + Save()
Config.Keys()                      ; итератор по известным клавишам
Config.GetSetting(name, default)   ; из секции [Windows]
Config.Path                        ; фактический путь к файлу (для сообщений)
Config.IsPortable                  ; режим
```

### 2.1 Определение пути (portable-first)

При старте, в указанном порядке:

1. Есть `config.ini` рядом с exe (`A_ScriptDir`) → использовать его. **Портабельный режим — приоритетный.**
2. Файла нет → проба записи в `A_ScriptDir` (создать и удалить temp-файл). Удалась → создать `config.ini` рядом, портабельный режим.
3. Запись не удалась (Program Files и т.п.) → использовать `%A_AppData%\hypetype\config.ini` (создать папку при необходимости). При **первом** переходе на AppData показать пользователю одноразовое сообщение: «Папка программы защищена от записи, настройки сохранены в: <путь>». Факт показа можно хранить самим существованием файла в AppData.

> Это чинит реальный баг v1: запись рядом с exe в Program Files попадает под UAC Virtualization и молча уезжает в VirtualStore («настройки не сохраняются»).

### 2.2 Загрузка и миграция

- Парсер — строго по FORMAT.md §2.1, §4. Один парсер на всю программу (в v1 их было два несовместимых — `main.ahk` пропускал «первые 2 строки», `editor.ahk` искал секцию; оба подхода выбросить).
- Файл есть, но нет `[hypetype]`/`version` → legacy: бэкап в `config.old.ini`, миграция по FORMAT.md §8.1, сохранение в новом формате. Пользователю — ничего не показывать (тихая миграция).
- Файла нет → создать из дефолтной раскладки. Дефолт — текущая раскладка из v1 `editor.ahk` (`defaultMapping`), перенесённая на W3C-имена; хранить в коде как Map `w3cName -> [altHex, altShiftHex]` уже в hex-виде.
- Битые строки не валят программу: предупреждение в `OutputDebug`/лог, строка пропускается (FORMAT.md §4.7).
- **Никакого ручного BOM.** Запись через `FileOpen(path, "w", "UTF-8-RAW")` (UTF-8 без BOM); чтение должно переживать BOM, если пользователь пересохранил файл Блокнотом.

### 2.3 Сохранение

- Атомарно: запись полного содержимого во временный файл `<config>.tmp` в той же папке → `FileMove` поверх целевого (перезапись). Без `FileDelete`-перед-move, без единого `Sleep` (в v1 были карго-культные `Sleep 20/50` — запрещены), без чтения-обратно-для-проверки (в v1 была проверка «длина файла > 100» — выбросить, atomic move достаточен).
- Автокомментарии по FORMAT.md §6.
- Round-trip по FORMAT.md §7: неизвестные секции (включая `[macOS]`) и ключи сохраняются. Для этого `Load()` должен складывать неопознанное в отдельное хранилище «как есть».
- На случай исключения при записи — temp-файл удаляется в `finally` (в v1 ранние `return` в обработчиках ошибок оставляли `temp.ini` на диске — не повторять).

### 2.4 Кодирование/декодирование hex

Две чистые функции (юнит-тестируемые, см. §8):
- `HexToString("0020+00B7+0020") -> " · "` — через `Chr()`. Валидация диапазона и суррогатов по FORMAT.md §4.1.
- `StringToHex(" · ") -> "0020+00B7+0020"` — **итерация по кодпоинтам, не по UTF-16 code units**: символы > U+FFFF (эмодзи) в AHK-строках лежат суррогатной парой; использовать `Ord()` + сдвиг индекса на 2 для пар (если `Ord() > 0xFFFF`, символ занимает 2 позиции строки).

### 2.5 Таблица клавиш

Статическая Map `W3C_TO_SC` (48 записей) из FORMAT.md §5, рядом — обратная. Это единственное место в коде, знающее про сканкоды-как-строки.

## 3. Модуль Registry (`registry.ahk`)

### 3.1 Класс ScancodeMap — самая ответственная часть проекта

Реестровое значение: `HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layout` → `Scancode Map` (REG_BINARY). Бинарный формат:

```
DWORD 0x00000000        ; header (version)
DWORD 0x00000000        ; flags
DWORD count             ; число 4-байтовых записей ВКЛЮЧАЯ нулевой терминатор
entry[count-1]          ; по 4 байта: WORD newScancode, WORD origScancode (little-endian)
DWORD 0x00000000        ; терминатор
```

Наша запись (как в v1): правый Alt `E0 38` → `E0 68` (после ребута система видит правый Alt как `vkA9`). В байтах записи: `68 E0 38 E0`. Минимальный блоб только с нашей записью — `00000000 00000000 02000000 68E038E0 00000000` (ровно тот, что v1 писала целиком).

**Поведение (ключевое отличие от v1 — НЕ перезаписывать чужое):**

- `Status()` → одно из: `none` (значения нет), `ours` (в блобе есть запись `origScancode == E0 38` с `newScancode == E0 68`), `foreign-ralt` (есть запись для `E0 38`, но с другим назначением — правый Alt уже переназначен другой программой), `other` (значение есть, нашей записи нет, правый Alt не тронут). Галочка «Виртуализация» в трее = `Status() == "ours"`. (В v1 проверялось только существование ключа — из-за этого галочка врала и «выключение» сносило чужие маппинги.)
- `Enable()`:
  1. Прочитать текущее значение (RegRead с типом REG_BINARY возвращает hex-строку — распарсить в массив записей; невалидный/обрезанный блоб → отказ с понятным сообщением, ничего не писать).
  2. Перед ЛЮБОЙ записью — бэкап: экспорт текущего значения в `scancode-backup.reg` рядом с конфигом (валидный .reg-файл, импортируемый двойным кликом; если значения не было — .reg, удаляющий наше значение). Сообщить пользователю путь к бэкапу в диалоге успеха.
  3. `none` → записать минимальный блоб. `other` → добавить нашу запись в существующий массив, инкрементировать count, записать объединённый блоб. `foreign-ralt` → **отказ**: «Правый Alt уже переназначен другой программой, hypetype не будет это перезаписывать», ничего не менять. `ours` → уже включено, no-op.
- `Disable()`: распарсить блоб, удалить **только нашу** запись. Остались чужие записи → записать уменьшенный блоб; наша была единственной → удалить значение целиком. Бэкап перед записью — так же.
- Требование прав: операции записи — только при `A_IsAdmin`, иначе вежливый отказ с предложением перезапустить от администратора (как в v1). Чтение/Status работает без прав.
- Реализация парсера/сериализатора блоба — **чистые функции** `ParseScancodeMap(hexString) -> Array of {new, orig}` и `BuildScancodeMap(entries) -> hexString`, без обращения к реестру (для тестов, §8).

### 3.2 Класс Autostart

Как в v1 (HKCU `...\Run`, значение `hypetype` = путь к exe), с одним фиксом: `IsEnabled()` сравнивает пути регистронезависимо и считает включённым только если путь совпадает с текущим exe; если в реестре чужой/устаревший путь — при включении перезаписывать на актуальный.

## 4. Модуль Input (`input.ahk`)

### 4.1 Регистрация хоткеев

- Префикс-клавиша: константа `MODIFIER := "vkA9"`. Хоткеи вида `vkA9 & SCxxx` для каждой клавиши из таблицы §2.5, обработчик — замыкание с W3C-именем: `Hotkey("vkA9 & " scCode, OnSymbolKey.Bind(w3cName))`.
- **Первое, что проверить после первой сборки:** что синтаксис `vkA9 & SCxxx` в v2 работает идентично v1 — это сердце программы (риск №1 проекта).
- Регистрировать хоткеи для **всех** 48 клавиш таблицы один раз при старте, независимо от наличия значения в конфиге (обработчик при пустом значении просто ничего не делает). Это чинит баг v1: после правки символа в редакторе хоткей продолжал вводить старое значение до перезапуска, потому что хоткеи регистрировались по снимку конфига. В v2 обработчик на каждом нажатии берёт актуальное значение через `Config.GetKey()` — правки применяются мгновенно, перезапуск не нужен.
- `vkA9 & Enter` → послать `{LAlt down}{Enter}{LAlt up}` (сохранить фичу v1 «Alt+Enter работает как обычно»).

### 4.2 Обработчик `OnSymbolKey(w3cName)`

1. `value := Shift зажат ? altShift : alt` (из `Config.GetKey`). Пусто → return.
2. Ровно один кодпоинт в 0300–036F → диакритический режим (§4.3).
3. Иначе → `SendText(value)` (v2-аналог SendRaw; выводит последовательности и эмодзи как есть). `SendMode "Input"`, `SetKeyDelay -1`.

Мёртвую логику v1 не портировать: ветка «склеить с висящей диакритикой» в `NumberKey` была недостижимой (режим сбрасывался синхронно до следующего вызова) — в v2 её нет вообще.

### 4.3 Диакритический режим

- Состояние — приватные поля модуля (не глобалы): `waitingDiacritic`, объект `InputHook`.
- Запуск: `ih := InputHook("L1 T" timeoutSec)`, где `timeoutSec := Config.GetSetting("DiacriticTimeoutMs", 3000)/1000`; `ih.KeyOpt("{Escape}", "E")` (Escape — end-key для отмены); `ih.VisibleText := false` (ввод перехватывается самим хуком). **`BlockInput` не использовать** — в v1 он глобально блокировал ввод до 5 секунд, это риск «зависшей» машины.
- ToolTip `«◌̋ Введите букву»` на время ожидания; убрать по любому исходу (одна функция-таймер, без лишних параметров — в v1 был баг `SetTimer, RemoveToolTip, -1200, %x%, %y%` с неопределёнными `x, y` в параметре Priority).
- Исходы: получен символ → `SendText(NormalizeNFC(char . diacritic))`; таймаут → ToolTip «Время ввода вышло»; Escape → ToolTip «Отменено». Во всех исходах состояние сбрасывается.
- Дефолтный таймаут — 3000 мс (записан в `[Windows]` конфига, FORMAT.md §3.3).

### 4.4 Нормализация

`NormalizeNFC(str)`: портировать из v1 (`Normaliz.dll` → `NormalizeString`, Form C = 1), заменив `VarSetCapacity` на `Buffer`, размер в WCHAR'ах × 2 байта. Ошибки DLL → вернуть исходную строку без MsgBox (тихий фолбэк + OutputDebug).

## 5. Модуль Editor (`editor.ahk`)

### 5.1 Главное окно

- v2 `Gui()`: 4 ряда × 12 кнопок по таблице клавиш, подпись кнопки — `имя_клавиши\nAltShift-символ\nAlt-символ` (как в v1). Клик → замыкание с W3C-именем (никакого обратного поиска «какая кнопка по имени переменной», как в v1 `KeyClick`).
- DPI-масштабирование размеров — сохранить подход v1 (`A_ScreenDPI/96`), шрифт Cambria.
- Для последовательностей длиннее ~3 символов на кнопке показывать первые символы + `…` (полное значение видно в окне правки).
- Текст-подсказка внизу окна — как в v1.
- Окно создаётся **лениво** при первом «Редактировать» (в v1 GUI строился при старте программы всегда).
- После каждого `Config.SetKey` подпись кнопки обновляется из конфига.

### 5.2 Окно правки клавиши

- Два поля: «Символ с Alt+Shift» (верхнее), «Символ с Alt» (нижнее) — пользователь вставляет **живые символы/последовательности**, как в v1. Hex пользователь не видит никогда.
- Кнопка «Сохранить» → валидация → `Config.SetKey(name, alt, altShift)` → обновить кнопку → закрыть окно.
- **Валидация:** убрать `\r`/`\n`; длина ≤ 32 кодпоинтов (считать кодпоинтами, не code units — эмодзи!), при превышении — сообщение и отказ от сохранения; всё остальное разрешено (запятые, `=`, `|`, `;` — hex-формат переваривает всё).
- **Пустое поле = «символ не задан»**, честно (FORMAT.md §4.4). Не подменять пробелом, как делала v1 (там «очистить» Alt-символ было невозможно — всегда оказывался пробел).

## 6. Точка входа (`hypetype.ahk`)

- Директивы: `#Requires AutoHotkey v2.0`, `#SingleInstance Force`, `Persistent`.
- Порядок init: `Config.Load()` → регистрация хоткеев → трей-меню. Весь init — явный, линейный, в одном месте (в v1 init-вызовы были разбросаны и часть оказывалась в недостижимом коде после границы auto-execute из-за `#Include` посреди файла — класс проблем, в v2 не существующий, но порядок всё равно держать явным).
- Трей-меню (паритет с v1): Выход · разделитель · Запуск при старте ✓ · Виртуализация ✓ · разделитель · Редактировать. Tooltip: `"hypetype " APP_VERSION`. Галочки — из `Autostart.IsEnabled()` и `ScancodeMap.Status() == "ours"`, обновлять после каждого toggle.
- Поведение пунктов «Виртуализация»/«Запуск при старте» и тексты сообщений (включая фирменные «Всё Чикаго!» и т.п.) — сохранить из v1, дополнив новыми статусами из §3.1 (foreign-ralt, путь к .reg-бэкапу).

## 7. Сборка (`.github/workflows/build.yml`)

Обновить workflow под v2:

1. Скачивать **AutoHotkey v2** (актуальный релиз из `AutoHotkey/AutoHotkey`).
2. Ahk2Exe для v2 распространяется отдельно (репозиторий `AutoHotkey/Ahk2Exe`) — скачать его релиз, компилировать с `/base` на бинарь v2 (`AutoHotkey64.exe`; перейти на 64-бит — v1 собиралась U32 без причины).
3. Пути: `src/hypetype.ahk` (новая структура), иконка `assets/icon.ico`, выход `hypetype.exe`.
4. `#Include`-файлы лежат рядом с главным скриптом — Ahk2Exe вкомпилирует их автоматически.
5. ВАЖНО: перед написанием workflow проверить актуальные URL/имена артефактов релизов обеих реп (могли измениться).

## 8. Тесты

### 8.1 Автотесты (скрипт `tests/run_tests.ahk`, запуск интерпретатором v2 в CI шагом перед компиляцией)

Чистые функции обязаны покрываться проверками (простые assert'ы с `ExitApp 1` при провале):

- `HexToString`/`StringToHex`: round-trip на наборе: ASCII, кириллица, `,` `=` `|` `;`, комбинирующая диакритика, эмодзи `1F60E` (суррогатные пары!), последовательность из 32 кодпоинтов, пустая строка; невалидный hex → корректный отказ.
- Парсер конфига: эталонный файл из FORMAT.md §9 → правильные значения; файл с BOM; битые строки не валят парсинг; round-trip `load→save→load` сохраняет `[macOS]` и неизвестные ключи.
- Миграция legacy: образец старого config.ini (взять реальный формат v1 c BOM-строкой) → корректный новый.
- `ParseScancodeMap`/`BuildScancodeMap`: пустой блоб; блоб только с нашей записью (эталон `00000000 00000000 02000000 68E038E0 00000000`); блоб с чужой записью + добавление нашей; удаление нашей из смешанного; обрезанный/невалидный блоб → отказ.

### 8.2 Чек-лист ручного тестирования (перед релизом, на реальной Windows-машине)

1. **Чистая установка:** запуск без config.ini → дефолт создан рядом с exe; формат соответствует FORMAT.md §9.
2. **Миграция:** подложить config.ini старого формата (со своей раскладкой!) → после запуска раскладка работает, `config.old.ini` создан, новый файл валиден.
3. **Виртуализация с нуля:** включить (от админа) → .reg-бэкап создан → ребут → правый Alt вводит символы; Alt+Enter работает; хоткеи Alt/Ctrl+Alt в Figma/Photoshop/браузере НЕ конфликтуют.
4. **Чужой Scancode Map:** руками внести в реестр постороннюю запись (например, CapsLock→Ctrl) → включить виртуализацию → после ребута работают ОБЕ; выключить → чужая запись осталась, наша ушла. Отдельно: запись с переназначенным правым Alt → программа отказывается, ничего не трогает.
5. **Символы:** одиночные; Shift-вариант; последовательность (`␣·␣`); каомодзи; эмодзи 😎 (в т.ч. в строке с другими символами); пустое значение — клавиша молчит.
6. **Диакритика:** Alt+Shift+V → ToolTip → `g` → `ǧ`; таймаут; отмена Escape; ввод во время ожидания не «проваливается» в активное окно.
7. **Редактор:** правка символа → ввод работает **сразу без перезапуска**; очистка поля → клавиша молчит; вставка последовательности с запятой и `|` внутри → сохраняется и вводится корректно; >32 кодпоинтов → отказ с сообщением.
8. **Пути:** exe в обычной папке → config рядом; exe в `C:\Program Files\hypetype\` → конфиг в AppData + одноразовое сообщение; ручной config.ini рядом с exe в Program Files → используется он (форсированный portable).
9. **Автозапуск:** включить → ребут → программа в трее; выключить → не стартует.
10. **Round-trip:** дописать в конфиг секцию `[macOS]` руками → отредактировать символ в GUI → секция на месте.
11. **Стресс ввода:** быстрые повторные нажатия Alt+символ; зажатие (автоповтор); ввод в elevated-окно (ожидаемо может не работать без админа — зафиксировать поведение).

## 9. Порядок работ

1. Прочитать `FORMAT.md` целиком.
2. `config.ahk`: hex-функции → парсер/сериализатор → миграция → путь. Сразу тесты §8.1.
3. `registry.ahk`: чистые функции блоба + тесты → классы поверх.
4. `input.ahk`: хоткеи, обработчик, диакритика, нормализация. **Сразу проверить `vkA9 & SCxxx` на машине.**
5. `hypetype.ahk`: трей, связывание.
6. `editor.ahk`: GUI.
7. `build.yml` + прогон тестов в CI.
8. Чек-лист §8.2 → правки → релиз как `v0.1.0` (минорный скачок — заслуженно: новый формат, v2, миграция).
