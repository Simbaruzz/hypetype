# hypetype Typograph — ТЗ на модуль `typograph.ahk`

Дополнение к `PLAN.md` и `FORMAT.md`. Новый модуль для hypetype v2 (AutoHotkey v2): автотипограф русского текста по хоткею **RAlt + Backspace** — выделенный текст в любом приложении заменяется типографированным. Полностью офлайн, без внешних зависимостей, правила — на встроенных регулярках (PCRE).

Ориентир качества: **не хуже SBOL Typograph** (https://github.com/DanilovM/SBOLTypograph) на золотом корпусе (§9), при этом исправляя его известные провалы (§9.2).

---

## 0. Цели и не-цели

**Цели:** типографика русского текста (кавычки, тире, пробелы, неразрывные, пунктуация, числа/валюта) одним нажатием, в любом поле ввода, мгновенно, идемпотентно.

**НЕ-цели (не делать):**
- Ёфикатор (е→ё) — требует словаря, не регулярок. Возможная будущая опция с мини-словарём однозначных слов; сейчас — нет.
- Телефонные номера — высокий риск ложных срабатываний; кандидат на будущую итерацию, выключенным по умолчанию.
- Корпоративная редполитика SBOL («вы/банк/приложение со строчной») — не типографика, не переносим.
- Словарь бренднейминга (Mastercard, ПИН-код, Wi-Fi…) — не сейчас; в архитектуре предусмотреть будущую секцию `[TypographDict]` (точные замены от пользователя), код не писать.
- Детект гомоглифов (латинская `c` в русском слове) — зафиксировано как известная проблема, не решаем.
- GUI настроек — не в этой итерации. Управление группами — через конфиг (§7). Возможное будущее: простое нативное окно с чекбоксами групп (v2 Gui, без WebView).

## 1. Архитектура

- Новый файл `src/typograph.ahk`, подключается из `hypetype.ahk` как остальные модули.
- Ядро — **чистая функция** `Typograph(text) -> text`: никакого GUI, буфера, хоткеев внутри. Только она покрывается автотестами.
- Правила — **данные, не код**: упорядоченный массив объектов `{group, pattern, replacement}` (для regex-правил) + две специальные процедуры, не выразимые одной регуляркой: автомат кавычек (§4) и группировка разрядов (§5.G6). Порядок применения фиксирован (§6).
- Хоткей и буферная механика — в `input.ahk` (`KeyInput`), по образцу существующих хоткеев: `Hotkey("vkA9 & SC00E", ...)` (Backspace).
- Все пользовательские строки (тултипы) — в `strings.ahk`.

## 2. Механика хоткея (RAlt + Backspace)

Пользовательский сценарий: выделил текст → **одно** нажатие RAlt+Backspace → выделение заменилось типографированным текстом. Повторное нажатие безвредно (§3).

Алгоритм обработчика:

1. `saved := ClipboardAll()` — сохранить буфер **целиком** (включая картинки/форматы).
2. `A_Clipboard := ""` → `Send("^c")` → `ClipWait(0.4)`.
3. **Не дождались** (ничего не выделено / приложение не отдало): ToolTip `«Выделите текст»` (мигнуть ~1.2 c, как FlashTip), восстановить `A_Clipboard := saved`, выход. Ничего не сломано.
4. Дождались: `result := Typograph(A_Clipboard)`.
5. `result == исходному` → ToolTip `«Уже типографировано ✓»`, восстановить буфер, выход (не дёргать вставку зря).
6. Иначе `A_Clipboard := result` → `Send("^v")` → пауза ~150 мс (приложению нужно успеть прочитать буфер до восстановления; константой, не магическим числом по коду) → `A_Clipboard := saved`.
7. ToolTip `«Типографировано ✓»` (FlashTip).

Краевые случаи и честные ограничения (отразить в README):

- **Форматирование заменённого фрагмента теряется** (вставляется plain text) — принципиальное свойство буферной механики, как и у SBOL-плагина. Known limitation.
- **Не применять к коду**: неразрывные пробелы невидимы и ломают исходники неотличимо для глаза. В README — жирное предупреждение. Детект кода не делаем.
- Undo: вставка = один шаг отмены в приложении, Ctrl+Z возвращает исходник — бесплатный «откат типографа», упомянуть в README.
- Многострочное выделение — поддерживается; правила обрезки пробелов работают построчно (§5.G4).
- Очень большой текст (сотни КБ) — допустимо; регулярки v2 справятся, но шаг 6 может потребовать паузу больше — если вставка нестабильна на больших объёмах, увеличить паузу пропорционально длине (зафиксировать при ручном тесте).

## 3. Идемпотентность — закон модуля

`Typograph(Typograph(x)) == Typograph(x)` для любого `x`. Каждое правило обязано не срабатывать на уже-правильном тексте (например, правило тире не трогает существующее `—`; автомат кавычек корректно проходит текст, где уже стоят «…„…“…»). Каждый тест корпуса (§9) автоматически прогоняется дважды: второй прогон обязан вернуть вход без изменений.

## 4. Автомат кавычек (группа G1) — самый сложный раздел

Одной регуляркой не решается: `"` симметричен, открывающая/закрывающая определяется контекстом и состоянием. Реализация — однопроходный конечный автомат по строке.

Состояние: `depth` (0 = вне кавычек, 1 = внутри «…», 2 = внутри „…“; глубже 2 — оставлять `"` как есть).

Классификация встреченного `"` (а также `«»„“`, уже присутствующих — они двигают состояние, но не заменяются — идемпотентность):

- **Дюйм-эвристика (приоритетная):** `"` непосредственно после цифры при `depth >= 1` — это знак дюйма, оставить как есть, состояние не менять. (`«Монитор 21"»` — корректный разбор; провал SBOL.) При `depth == 0` после цифры — тоже считать дюймом (`диагональ 27"`).
- **Открывающая:** перед `"` — начало строки, пробел, `(`, `[`, тире; после — не-пробел. Замена: `depth 0 → «` (depth=1), `depth 1 → „` (depth=2).
- **Закрывающая:** перед `"` — не-пробел; после — конец строки, пробел, знак препинания, `)`, `]`. Замена: `depth 2 → “` (depth=1), `depth 1 → »` (depth=0).
- **Неоднозначный** (зажат между не-пробелами): трактовать по состоянию — `depth > 0` → закрывающая, иначе открывающая.
- **Апостроф:** одиночная `'` внутри латинского слова (`it's`, `d'Artagnan`) → `’`; прочие `'` не трогать. Штрихи `5'10"` — `'` после цифры не трогать.
- Несбалансированность на конце строки/текста (depth не вернулся в 0) — не ошибка: оставить как получилось, не «чинить» задним числом.

После автомата — правило «точка/запятая за закрывающую кавычку» (из SBOL): `«…деньги.»` → `«…деньги».` (только для `.` и `,`, не для `!?`).

## 5. Группы правил

Все замены ниже обязаны быть идемпотентными. НБ = неразрывный пробел U+00A0. Примеры — формат «до → после».

### G1. Quotes — кавычки
См. §4. `"привет" → «привет»`; `«сказал "да"» → «сказал „да“»`; `"Монитор 21"" → «Монитор 21"»`; `it's → it’s`.

### G2. Dashes — тире
- Начало строки/предложения: `^- ` или `. - ` → `— ` c НБ после тире… **поправка по SBOL**: длинное тире + НБ *после* тире в начале прямой речи: `- Это я → — Это я` (НБ между — и Это).
- Внутри текста: ` - ` (пробел-дефис-пробел, также `--`, `–` в той же позиции) → `НБ—пробел`: `гений и злодейство - две вещи → гений и злодейство — две вещи` (перед — НБ).
- Диапазоны чисел: `2002-2009 → 2002–2009` (среднее тире, без пробелов; также римские `XI-XII`). НЕ трогать: даты `12-05-2024`, телефоноподобные цепочки, слова с дефисом.
- Диапазоны месяцев/дней: `январь-март → январь–март`, `понедельник-суббота → понедельник–суббота` (закрытый список слов: 12 месяцев + 7 дней, оба слова из списка).
- Висячий дефис между словами `кто-то`, `по-русски` — НЕ трогать (дефис без пробелов между буквами).

### G3. Punct — многоточие и пунктуация
- `... → …` (ровно три и более точек подряд → одно …; `!!! → !`, `??? → ?` — схлопывание повторов `?!.,;:` до одного).
- `!? → ?!`.
- Стиль SBOL для смешанных: `...? → ?‥`, `...! → !‥`, `?... → ?‥`, `!... → !‥` (U+2025 ‥). Идемпотентность: `?‥` не трогается.

### G4. SpaceClean — чистка пробелов
- Убрать пробел после `« „ ( [` и перед `. … : , ; ? ! » “ ) ]`.
- **Добавить пробел после `,` `;` `:` перед буквой**, если его нет: `менее,меньше → менее, меньше` (системный провал SBOL). Исключения: десятичные дроби `143,56`, время `12:30`, числовые контексты `1:0` — после знака цифра → не трогать.
- Двойные+ пробелы → один (НЕ схлопывать НБ-конструкции, уже расставленные нашими же правилами; внутри строки любые последовательности обычных пробелов → один обычный).
- Обрезка пробелов в начале/конце **каждой строки** (построчно, переносы строк сохраняются).
- `23 % → 23%` — процент слитно (дефолт; см. настройку §7 `PercentSpace`).

### G5. Nbsp — неразрывные пробелы
Замена обычного пробела на НБ в позициях:
- После короткого слова (1–3 буквы) — список из SBOL как массив данных: предлоги/союзы/частицы (`а, без, в, во, для, до, же, за, и, из, к, ко, на, над, не, ни, но, о, об, от, по, под, при, про, с, со, то, у, что, чтобы…` — полный список из приложенного описания SBOL) + сокращения (`г., ул., д., кв., рис., гл., ст., п.…` — полный список оттуда же) + `№ §` и орг-формы (`АО, ООО, ПАО…`).
- Перед частицами `б, бы, ж, же, ли, ль`.
- Между числом и следующим словом: `5 лет → 5НБлет`.
- Инициалы: `А.А. Иванов` → НБ между инициалами и фамилией (оба порядка: `Петров К.П.`).
- Перед `и т.д., и т.п., и др.` (и внутри них).
- Перед последним коротким словом (1–3 символа) строки/предложения.

### G6. Numbers — числа и валюта
- `руб., руб, р., RUR, RUB → ₽`; `USD, usd → $`; `EUR, eur → €` (только в позиции у числа).
- Знак валюты — **после** числа (дефолт `CurrencyPosition=after`, §7) через НБ: `$ 109 → 109 $`, `109$ → 109 $`, `20usd → 20 $`.
- Группировка разрядов **только у числа при знаке валюты** (≥5 цифр): `2345123 $ → 2 345 123 $` (разделитель — НБ; реализация — процедурой, не регуляркой). Прочие длинные числа (годы, ID, индексы) — НЕ трогать.
- Десятичная точка → запятая **только в валютном контексте**: `143.56 $ → 143,56 $`. Версии `2.5.1`, IP и пр. — не трогать.
- Копейки в сумму: `45 руб. 5 коп. → 45,05 ₽`.
- `тыс.` с точкой; `млн, млрд, трлн` без точки.

### G7. Symbols — символы
`(c)/(C) → ©`, `(r)/(R) → ®`, `(tm) → ™`, `+- → ±`, `№ 5 → №НБ5` (НБ после №, пробел убрать… поправка: SBOL-стиль — `№` + НБ + число). Не трогать `(с)` в скобках-перечислениях `а) б) в)` — только точное `(c)` латиницей/кириллицей без соседних букв.

## 6. Порядок применения

Фиксированный конвейер (порядок критичен, менять нельзя):
`G4-обрезка краёв → G1 кавычки (автомат) → G3 пунктуация → G2 тире → G4 чистка пробелов (вкл. запятые) → G6 числа/валюта → G7 символы → G5 неразрывные (последними — работают по уже расставленным пробелам) → финальная G4-чистка двойных пробелов`.

## 7. Конфигурация — секция `[Typograph]`

По FORMAT.md §3.3 (платформенная логика — но секцию назвать `[Typograph]`, она потенциально общая с будущей mac-версией; round-trip правила действуют). Все группы включены по умолчанию; отсутствие ключа = значение по умолчанию.

```
[Typograph]
Quotes=1
Dashes=1
Punct=1
SpaceClean=1
Nbsp=1
Numbers=1
Symbols=1
PercentSpace=none        ; none = 23% слитно (дефолт) | narrow = U+202F: 23 %
CurrencyPosition=after   ; after = 109 $ (дефолт) | before = $ 109
```

`Typograph(text, settings)` принимает настройки параметром (чистота функции, тестируемость); обработчик хоткея читает их из `Config.GetSetting`-аналога для секции `[Typograph]`.

## 9. Тесты

### 9.1 Автотесты (в `tests/run_tests.ahk`, тот же раннер)

- По каждой группе — минимум все примеры «до → после» из §5 (каждый пример = тест).
- **Каждый тест гоняется дважды** (§3): второй прогон не меняет текст.
- Негативные тесты (текст НЕ должен измениться): `кто-то`, `по-русски`, `12-05-2024`, `2.5.1`, `12:30`, `143,56`, `1:0`, `it’s` (уже правильный), `27"` после цифры, год `2026` без валюты, `?‥` (уже SBOL-стиль).
- Тумблеры: каждая группа выключается и её правила не применяются; `PercentSpace=narrow` даёт U+202F; `CurrencyPosition=before` даёт `$ 109`.

### 9.2 Золотой корпус

Тест №1 — эталонная «фраза-пытка» (вход):

```
"-" - это минус, читайте статью "про минус" ! Ми́нус (от лат. minus "менее ,меньше") - математический cимвол " -" . Между тем ,внутри "елочек" дюймы остаются - "Монитор 21""!
```

Ожидаемый выход (НБ помечены `⍽` для наглядности, в тесте — реальный U+00A0):

```
«-» — это минус, читайте статью «про минус»! Ми́нус (от лат. minus «менее, меньше») — математический cимвол «-». Между тем, внутри «елочек» дюймы остаются⍽— «Монитор 21"»!
```

Осознанные расхождения с ручным идеалом (НЕ чинить): `-` внутри кавычек не становится минусом U+2212 (семантика, не типографика); `елочек` без ё (нет ёфикатора); латинская `c` в `cимвол` не детектится (гомоглифы вне скоупа). Известные провалы SBOL, которые этот тест ловит у нас: дефисы→тире у кавычек, пробел после запятой, дюймы внутри ёлочек.

Тесты №2–N — реальные пары «до/после» из рабочих текстов (прогнанные через SBOL-плагин и выправленные вручную) — добавляются владельцем проекта в `tests/corpus/` как пары файлов `NNN.in.txt` / `NNN.out.txt`; раннер подхватывает все пары автоматически.

### 9.3 Ручной чек-лист

1. Выделение + RAlt+Backspace в: Блокнот, браузерное поле (Google Docs!), Telegram, Word, Figma (текстовый слой), VS Code (убедиться, что работает, и лично прочувствовать, почему README запрещает код :)).
2. Нажатие без выделения → ToolTip, буфер цел (проверить: скопировать картинку → нажать без выделения → вставить картинку — она на месте).
3. Буфер с картинкой → типографирование текста → после операции вставка возвращает картинку (восстановление ClipboardAll).
4. Двойное нажатие подряд → текст не изменился вторым прогоном, ToolTip «Уже типографировано».
5. Многострочный текст с абзацами → переносы сохранены.
6. Большой текст (статья ~50 КБ) → работает, вставка полная.
7. Ctrl+Z после типографирования → исходный текст вернулся.
8. Выключить группу в конфиге → правила группы не применяются без перезапуска приложения (настройки читаются на каждом нажатии, как раскладка).

## 10. Порядок работ и риски

Порядок: чистая функция + конвейер на стабах → G3/G4/G7 (простые regex) → автомат кавычек G1 + его тесты → G2 → G6 → G5 (списки слов как данные) → фраза-пытка зелёная → буферная механика в input.ahk → ручной чек-лист.

| Риск | Митигация |
|---|---|
| Автомат кавычек — краевые случаи | самый подробный раздел §4; дюйм-эвристика; негативные тесты; несбалансированность ≠ ошибка |
| ClipWait/вставка в медленных приложениях | таймауты константами; пункт 1 чек-листа по списку приложений; пауза перед восстановлением буфера |
| Регулярка съедает не своё (даты, версии, время) | негативный корпус §9.1 обязателен ДО включения правила в конвейер |
| Нарушение идемпотентности новым правилом | двойной прогон каждого теста в раннере — ловится автоматически |
| Конфликт порядка правил | порядок §6 фиксирован; новые правила встраиваются только с прогоном всего корпуса |
