# hypetype Layout Format v2 — спецификация

Единый кросс-платформенный формат файла раскладки для hypetype (Windows / AutoHotkey v2) и hypetype-mac (macOS / Swift). Этот документ — контракт между платформами: обе реализации обязаны читать и писать файл строго по этой спецификации.

**Статус:** утверждён. Изменения формата требуют инкремента `version` и кода миграции в обеих программах.

---

## 1. Цели формата

1. **Переносимость:** один файл раскладки работает на Windows и macOS без конвертации. Скопировал файл — раскладка переехала.
2. **Устойчивость:** никакой пользовательский символ (включая `,` `=` `|` `;` переводы строк, эмодзи, комбинирующую диакритику) не может сломать парсинг, потому что символы хранятся как hex-кодпоинты, а не как литералы.
3. **Читаемость:** автокомментарии с живыми символами позволяют читать файл глазами.
4. **Простота:** формат должен парситься на любой платформе ~30 строками кода без сторонних библиотек (нет JSON/YAML-зависимостей в AHK).

## 2. Файл

- **Имя:** `config.ini`
- **Кодировка:** UTF-8 **без BOM**. Реализации обязаны корректно читать файл и с BOM (на случай ручного редактирования в Notepad), но писать — всегда без BOM.
- **Переводы строк:** при записи — нативные для платформы (`\r\n` на Windows, `\n` на macOS). При чтении принимаются оба варианта.
- **Структура:** INI-подобная — секции `[Name]`, строки `key=value`, комментарии после `;`.

### 2.1 Правила парсинга строки

1. Всё после первого символа `;` в строке отбрасывается (комментарий).
2. Строка триммится по краям (пробелы, табы).
3. Пустая строка после п.1–2 — игнорируется.
4. Строка вида `[Name]` — начало секции.
5. Строка вида `key=value` — пара ключ-значение текущей секции. Разделитель — первый `=`. Ключ и значение триммятся.
6. Любая строка, не подходящая под п.4–5 — игнорируется молча (forward-совместимость).

> Безопасность парсинга гарантирована тем, что в значениях нет литеральных пользовательских символов — только `[0-9A-F]`, `|`, `+`. Поэтому `;` `=` `[` `]` внутри значений невозможны по построению.

## 3. Секции

| Секция | Назначение | Кто читает |
|---|---|---|
| `[hypetype]` | Метаданные файла | обе платформы |
| `[Layout]` | Раскладка (переносимая часть) | обе платформы |
| `[Windows]` | Платформенные настройки Windows | только Windows |
| `[macOS]` | Платформенные настройки macOS | только macOS |

### 3.1 `[hypetype]`

```
[hypetype]
version=2
```

- `version` — **версия формата** (не версия приложения!). Сейчас `2`. Файл без секции `[hypetype]` или без `version` считается legacy-форматом и подлежит миграции (см. §8).

### 3.2 `[Layout]` — раскладка

Каждая строка: `<KeyName>=<AltValue>|<AltShiftValue>  ; <автокомментарий>`

- `KeyName` — платформо-нейтральное имя физической клавиши по стандарту W3C UI Events `code` (см. таблицу в §5). Регистрозависимое: `Digit1`, не `digit1`.
- `AltValue` — что вводится при `Hyper + клавиша` (Hyper = правый Alt на Windows, правый Option на macOS).
- `AltShiftValue` — что вводится при `Hyper + Shift + клавиша`.
- Разделитель значений — ровно один `|`.

### 3.3 `[Windows]` / `[macOS]`

Платформенные настройки. Текущий минимум:

```
[Windows]
DiacriticTimeoutMs=3000

[macOS]
DiacriticTimeoutMs=3000
```

Каждая платформа читает **только свою** секцию. Чужая секция подчиняется правилу round-trip (§7).

## 4. Синтаксис значения

```
value          = sequence
sequence       = codepoint *( "+" codepoint )   ; 1..32 кодпоинтов
codepoint      = 1*6HEXDIG                       ; верхний регистр, без префиксов
empty value    = ""                              ; пустая строка = «не задано»
```

### Правила

1. **Кодпоинт** — hex-номер символа Unicode без префикса `U+`/`0x`, в верхнем регистре, без ведущих нулей сверх необходимого (рекомендация: минимум 4 знака для читаемости, т.е. `0020`, но парсер обязан принимать и `20`). Допустимый диапазон: `0`–`10FFFF`, исключая суррогаты `D800`–`DFFF`.
2. **Последовательность** — кодпоинты, соединённые `+`, выводятся подряд в указанном порядке. Это первоклассная фича (каомодзи, дивайдеры, любые комбо). **Лимит: 32 кодпоинта** на значение. При загрузке значения длиннее лимита — обрезаются до 32 с предупреждением в лог.
3. **Эмодзи и символы за пределами BMP** (> `FFFF`) записываются одним кодпоинтом: `1F60E` = 😎. Никаких суррогатных пар в файле.
4. **Пустое значение** — символ не назначен. `KeyT=2122|` означает: Alt вводит ™, Alt+Shift не делает ничего. `KeyT=|2122` — наоборот. Пустота легальна с любой стороны.
5. **Полностью пустая клавиша** (`KeyT=|`) — допустима, эквивалентна отсутствию строки.
6. **Неизвестное имя клавиши** — не ошибка: игнорируется при загрузке, сохраняется при записи (round-trip, §7). Это покрывает клавиши, существующие только на одной платформе (например, `IntlBackslash` на ISO-клавиатурах).
7. **Невалидное значение** (не-hex символы, два `|`, кодпоинт вне диапазона) — строка игнорируется с предупреждением в лог, программа продолжает работу. Падать из-за одной битой строки нельзя.

### Семантика диакритики

Если значение состоит **ровно из одного** кодпоинта в диапазоне `0300`–`036F` (Combining Diacritical Marks) — нажатие включает **режим ожидания**: программа ждёт следующий введённый символ (таймаут `DiacriticTimeoutMs`), склеивает «символ + диакритика», нормализует в NFC и выводит результат.

Любое другое значение — включая последовательности, даже состоящие из диакритик — выводится напрямую без режима ожидания.

## 6. Автокомментарии

При сохранении реализация **обязана** дописывать к каждой строке `[Layout]` комментарий с живыми символами — единственный механизм человекочитаемости файла:

```
KeyH=20BD|030B          ; ₽ | ◌̋
Space=0020+00B7+0020|   ; ␣·␣ |
Comma=00AB|201E         ; « | „
```

Правила рендеринга комментария:

1. Формат: `; <Alt-представление> | <AltShift-представление>`.
2. Комбинирующая диакритика (0300–036F) показывается на носителе `◌` (U+25CC): `◌̋`, чтобы была видима.
3. Невидимые символы заменяются на условные обозначения: `0020`→`␣`, `00A0`→`⍽` (nbsp), `200B`→`​ZWSP`, прочие управляющие/невидимые → `·U+XXXX·`.
4. Пустое значение рендерится как `—`.
5. При **чтении** комментарии полностью игнорируются. Источник истины — только hex. Рассинхрон комментария и hex (после ручной правки) не является ошибкой; при следующем сохранении комментарий регенерируется из hex.

## 7. Round-trip: сохранение чужих данных

Критическое правило переносимости. При сохранении файла реализация обязана:

1. **Сохранять неизвестные секции целиком** (включая их комментарии) — Windows-программа не трогает `[macOS]` и наоборот; будущие секции формата тоже переживают сохранение.
2. **Сохранять неизвестные ключи** внутри `[Layout]` и своей платформенной секции — как есть, байт-в-байт по значению (комментарий можно регенерировать только для известных ключей).
3. Порядок: `[hypetype]`, `[Layout]` (в порядке таблицы §5, неизвестные ключи — после известных, в исходном порядке), затем платформенные секции.

Тест round-trip обязателен: `load(file) → save() → load()` не должен терять ни одной секции/ключа.

## 8. Миграция legacy-форматов

Файл без `[hypetype]`/`version` — legacy. Перед миграцией создаётся бэкап `config.old.ini` (Windows) / `config.json.old` (macOS) рядом с исходным файлом.

### 8.1 Windows legacy (INI v1)

Признаки: возможный BOM отдельной строкой, секция `[KeyMappings]`, ключи `SCxxx`, значения — литеральные символы через запятую (`SC002=¹,¡`).

Алгоритм: пропустить BOM-мусор; для каждой строки `SCxxx=a,b` → разбить по **первой** запятой (символ1 до неё, символ2 после; если запятых нет — символ2 пуст), сконвертировать каждый символ посимвольно в hex-кодпоинты через `+`, ключ `SCxxx` → W3C-имя по таблице §5. Известное ограничение: legacy-значения, содержавшие запятую внутри символа, в старом формате уже были битыми — мигрируются как есть, без попытки восстановления.

### 8.2 macOS legacy (JSON)

Признак: файл `config.json`, массив объектов `{keyCode, normal, shift, comment}`. Алгоритм: `keyCode` (десятичный int) → W3C-имя по таблице §5; строки `normal`/`shift` посимвольно → hex с `+`. Внимание: Swift `String` итерируется по графемам — конвертация обязана идти по **Unicode scalars**, иначе эмодзи/диакритика дадут неверные кодпоинты.

## 9. Эталонный пример файла

```
[hypetype]
version=2

[Layout]
Digit1=00B9|00A1            ; ¹ | ¡
Digit2=00B2|00BD            ; ² | ½
Minus=2014|2013             ; — | –
Equal=2260|00B1             ; ≠ | ±
KeyE=20AC|2325              ; € | ⌥
KeyH=20BD|030B              ; ₽ | ◌̋
KeyV=2193|030C              ; ↓ | ◌̌
Comma=00AB|201E             ; « | „
Period=00BB|201C            ; » | “
Slash=2026|0301             ; … | ◌́
Backslash=007C|005C         ; | | \
Space=0020+00B7+0020|00A0   ; ␣·␣ | ⍽
KeyT=1F60E|                 ; 😎 | —

[Windows]
DiacriticTimeoutMs=3000

[macOS]
DiacriticTimeoutMs=3000
```

Обрати внимание на строку `Backslash`: пользовательский символ `|` хранится как `007C` и не конфликтует со структурным разделителем — в этом смысл hex-формата.
